# Review: Configuration System requirements

## Sync drift: 2026-10-19

### Blocking: the SecretRef provider model and the secrets runtime are not covered by any requirement

- Artifact says (requirements.md:30): "**FR-7** | Must | The system shall support multiple methods of auth configuration (env vars, config file, credentials file)".
- Artifact lists no requirement for secret providers, secret resolution, or the secrets operator lifecycle.
- Code: `src/secrets/ref-contract.ts:4` defines `export type SecretRefSource = "env" | "file" | "exec" | "store";`, and `src/secrets/ref-contract.ts:7-16` documents the `{ source, provider, id }` shape for each source.
- Code: `src/config/zod-schema.core.ts:47-103` defines the `env`, `file`, `exec`, and `store` provider schemas, and `SecretsConfigSchema` in `src/config/zod-schema.core.ts` adds `providers` and per-source `defaults` (env, file, exec, store) to the `secrets` config block.
- Code: `src/secrets/resolve.ts`, `src/secrets/runtime.ts`, and `src/secrets/runtime-state.ts` implement runtime resolution, and `src/secrets/store/secret-store.ts` and `src/secrets/store/secret-store-sqlite.ts` implement the SQLite-backed secret store.
- Code: `src/cli/secrets-cli.ts:104-330` registers `openclaw secrets reload`, `openclaw secrets audit --check`, `openclaw secrets configure`, and `openclaw secrets apply`, with `--allow-exec` gating exec provider preflight and `openclaw secrets apply` consuming a generated plan file.
- Code: `src/secrets/runtime-source-contract.ts` and `src/secrets/target-registry.ts` define which config surfaces may hold a SecretRef and which targets are audited.
- Impact: FR-7 names three coarse "methods of auth configuration" and omits the four-source SecretRef contract, the provider defaults, the secret store, and the audit/configure/apply operator lifecycle, all of which are first-class configuration concerns today.
- Classification: blocking.

- Code: `scripts/generate-bundled-channel-config-metadata.ts` is the bundled channel config metadata generator, wired as `pnpm check:bundled-channel-config-metadata` (`package.json:1777`) and `pnpm config:channels:check` (`package.json:1830`).
- Code: the generated artifact is `src/config/bundled-channel-config-metadata.generated.ts`, whose header reads "Auto-generated by scripts/generate-bundled-channel-config-metadata.ts. Do not edit directly."
- Code: `src/config/schema-base.ts` computes the base JSON Schema at runtime, and `src/config/schema.base.generated.test.ts` asserts the computed schema shape.
- Code: `openclaw config schema` and `openclaw config validate` are the operator-facing surfaces (`src/cli/config-cli.ts:214`, `src/cli/config-cli.ts:359`).
- Impact: a reader of the artifact would not know that a generated config schema surface exists, and the open question is stale.
- Classification: blocking.

### Advisory: the single-file constraint does not mention the include chain or the state-directory override

- Artifact says (requirements.md:44): "Config is stored as a single JSON file (`openclaw.json`) by default".
- Code: `src/config/paths.ts:35` sets `const CONFIG_FILENAME = "openclaw.json";` and `src/config/paths.ts:241` resolves it under the state directory, so the "by default" wording is correct.
- Code: `src/config/includes.ts:1-11` documents a `$include` directive that merges other files into the document, `src/config/includes.ts:25-26` sets `INCLUDE_KEY = "$include"` and `MAX_INCLUDE_DEPTH = 10`, and the module adds a cycle check and a 2 MiB per-file limit.
- Code: `src/config/source-file.ts:34` exposes `createConfigFileAdapter`, which watches the config file plus every included path, so the effective config is a file set, not one file.
- Impact: the constraint is technically satisfied by the "by default" qualifier, but the include mechanism is the main way the file is extended and is not mentioned.
- Classification: advisory.
