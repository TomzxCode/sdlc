## Sync drift: 2026-10-19

- API Contracts drift: the scripts row lists `GET/PUT/DELETE | /api/scripts...`, but the code has no PUT. `packages/dashboard/src/routes/register-messaging-scripts.ts:19` registers GET, `:38` registers POST, `:70` registers DELETE, and `:93` registers `POST /api/scripts/:name/run`, which the table does not list.
- API Contracts drift: the table has no row for the mailbox messaging endpoints that the same registrar exposes. `packages/dashboard/src/routes/register-messaging-scripts.ts:232-608` registers the `/api/messages/*` and `/api/agents/*/mailbox` routes listed in `review-requirements.md`.
- API Contracts drift: the attachment row omits the message-attachment endpoint. `packages/dashboard/src/routes/register-chat-room-routes.ts:485` registers `POST /api/chat/rooms/:id/messages/:messageId/attachments`.
- API Contracts drift: the table has no row for the room event stream. `packages/dashboard/src/sse.ts:1054-1082` publishes the eight `chat:room:*` events on `/api/events`.
- API Contracts drift: the room message endpoints accept no metadata, so the request contract is narrower than the room message data model implies. `packages/dashboard/src/routes/register-chat-room-routes.ts:351-356` reads only `content`, `senderAgentId`, `mentions`, and `attachments`.
- Architecture drift: the Overview and the diagram omit the direct chat session registrar. `packages/dashboard/src/routes/register-chat-routes.ts` is a separate registrar mounted next to the room registrar in `packages/dashboard/src/routes/create-api-routes-mount-sequence.ts:11`, and it owns the session, tag, stream, and cancel endpoints.
- Architecture drift: the Overview and the diagram do not record that the dashboard no longer renders rooms. `packages/dashboard/app/components/ChatView.tsx:846-850` and `packages/dashboard/app/components/ChatView.tsx:3067-3070` state that rooms were removed from the Chat view, so the `UI[ChatView + chat services]` node in the diagram no longer reaches the room routes.
- Architecture drift: the diagram has no node for the PostgreSQL chat tables, while the feature brief names `packages/core/src/postgres/schema/project.ts` as an implementation surface. The `chat_rooms`, `chat_room_members`, `chat_room_messages`, and `chat_token_usage` tables are defined at `packages/core/src/postgres/schema/project.ts:2603-2660` and `:2362-2385`.
- Data Models drift: the ChatRoom table omits `name`, `description`, `projectId`, `createdBy`, `createdAt`, and `updatedAt`. The full shape is at `packages/core/src/chat/chat-types.ts:314-330` and `packages/core/src/postgres/schema/project.ts:2603-2628`.
- Data Models drift: the slug constraint is described as `unique, not null`, but uniqueness is scoped per project. `packages/core/src/postgres/schema/project.ts:2624` declares `uniqueIndex("idxChatRoomsSlug").on(t.projectId, t.slug)`, and `packages/core/src/chat/chat-store.ts:584-590` checks the conflict against the room's own project.
- Data Models drift: the ChatRoomMember table omits `role` and `addedAt`. `packages/core/src/chat/chat-types.ts:332-337` and `packages/core/src/postgres/schema/project.ts:2631-2640` define both, and `role` is constrained to `owner` or `member`.
- Data Models drift: the spec has no ChatRoomMessage model, which is the main stored entity of the feature. `packages/core/src/chat/chat-types.ts:339-350` defines `ChatRoomMessage` with `role`, `content`, `thinkingOutput`, `metadata`, `attachments`, `senderAgentId`, and `mentions`, and `packages/core/src/postgres/schema/project.ts:2646-2660` stores it.
- Data Models drift: the spec has no model for chat token usage. `packages/core/src/postgres/schema/project.ts:2362-2385` defines the `chat_token_usage` table that backs Command Center token totals.
- Key Sequences drift: the upload sequence says the system basenames the filename, verifies containment, and streams to disk, but the upload route does none of those three. `packages/dashboard/src/routes/register-chat-room-routes.ts:439-442` replaces every character outside `[a-zA-Z0-9._-]` with an underscore, prefixes a timestamp, and writes the whole buffer with `writeFile`. The basename and containment check live on the download route, at `packages/dashboard/src/routes/register-chat-room-routes.ts:31-42` and `:468`.
- Key Sequences drift: the post message sequence says the system validates metadata, but the room route validates only content and attachments. `packages/dashboard/src/routes/register-chat-room-routes.ts:359-372`.
- Key Sequences drift: the post message sequence calls reply generation optional, but a room with members always triggers it. `packages/dashboard/src/chat.ts:2249-2256` throws `RoomReplyGenerationError` when a room has members and no responder can be resolved.
- Technical Decisions drift: the decision that rate limits are split across reads and writes does not hold for the messaging and scripts routes, which have no rate limiting at all. `packages/dashboard/src/routes/register-messaging-scripts.ts` has no `rateLimit` import.
- Technical Decisions drift: the decision that only PlanningMode chat belongs to FEAT-p3 leaves the direct chat session surface unassigned. `packages/dashboard/src/routes/register-chat-routes.ts:415-1780` implements session creation, tags, message sends, SSE streaming, cancellation, and attachment upload and download.
- Technical Decisions drift: the spec does not record the responder routing rules, the per-room thinking level default, or the room token accounting that the code implements. `packages/dashboard/src/chat.ts:2132-2185` covers routing, `packages/core/src/postgres/schema/project.ts:2620` covers the thinking level, and `packages/dashboard/src/chat.ts:2292-2302` covers token accounting.
- Overview drift: the Overview says attachments are stored with basename and prefix validation, but the room upload path has no prefix validation. `packages/dashboard/src/routes/register-chat-room-routes.ts:31-42` and `:439-442` show basename and character-class sanitization only.
- Risks and Unknowns drift: the only listed risk is room-to-task linking, but the larger open question is whether the removed room UI returns. `packages/dashboard/app/components/ChatView.tsx:846-850` and `packages/dashboard/app/hooks/useChatRooms.ts` show an API-only surface with an orphaned hook.
